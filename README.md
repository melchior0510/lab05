ECONNREFUSED нь интерфейсийн (холболтын) алдаа: server ажиллаагүй тул хариу ирээгүй, oracle шалгагдаагүй. Харин FAIL ажиллуулалтад server хариу өгсөн боловч хүлээсэн 200 нь бодит 201-тэй таарсангүй, энэ нь oracle-ийн алдаа.


## Дүгнэлт

Дизайны 5 алхмаас хамгийн их бодол шаардсан нь сонголтуудыг тодорхойлж, төлөөлөх утгуудыг сонгох алхам байлаа, учир нь аль сонголт аль алдаатай холбогдохыг server-ийн кодоос нь ойлгох шаардлагатай болсон. Эхэндээ студентийн статус, үзсэн хичээл, хичээлийн урьдач нөхцөл гурвыг бүгдийг нь бие даасан сонголт гэж үзсэн боловч бодит байдал дээр заримынх нь хослол утга алдагддаг гэдгийг олж харсан. Тухайлбал оюутан байхгүй үед түүний status болон coursesTaken гэсэн сонголт байхгүй болно, мөн хичээл байхгүй үед prerequisites гэсэн сонголт утгаа алдана, эдгээр нь боломжгүй хослол байв. Заавар нэг хүсэлтэд хэд хэдэн алдаа зэрэг байвал аль нь буцахыг заагаагүй тул 7, 8-р тестээр үүнийг өөрөө тогтоосон. Үр дүнд нь server оюутны шалгалтыг хичээлийн шалгалтаас өмнө, хичээлийн шалгалтыг урьдач нөхцлийн шалгалтаас өмнө хийдэг нь нотлогдсон. Тест бүрийг бие даасан байлгахын тулд тест бүр өөрийн ID-тай оюутан, хичээлээ өөрөө PUT-аар үүсгэсэн тул ажиллуулах дараалал үр дүнд нөлөөлөхгүй. registrationID нь сервер асаалттай байх хугацаанд хуримтлагддаг тул яг утгыг нь биш, тоо мөн эсэхийг л шалгасан. Нийт 10 тест, 24 assertion бүгд PASS болж, Newman-ы гаралт results/newman-pass.txt дотор байна. Зориуд буруу oracle бүхий collection нь 1 assertion fail болж exit code 1 өгснөөр CI quality gate-ийн зарчмыг харуулсан, харин server зогссон үед ECONNREFUSED гарсан нь oracle-ийн биш, холболтын алдаа гэдгийг ялгаж үзүүлсэн. Миний тестүүд server-ийн кодод согог илрүүлээгүй, учир нь бүх хүлээгдэх үр дүн server-ийн бодит үйлдэлтэй таарсан, гэхдээ шалгах дараалал заавар дээр тодорхойгүй байсныг тестээр тодруулсан нь чухал үр дүн байлаа.
